# 需求文档分解为Feature

此技能帮助您将复杂的需求文档分解为结构化的feature文件，便于开发团队理解和实施。

## 使用步骤

### 1. 分析需求文档
- 识别核心系统/产品
- 理解主要功能领域
- 确定技术架构和约束

### 2. 识别核心功能模块
- 从需求中提取主要功能组件
- 按逻辑关系分组相关功能
- 确定模块间的依赖关系

### 3. 确定开发顺序
- 基于技术依赖确定开发顺序
- 基础组件优先，高级功能后续
- 考虑业务价值和风险评估

### 4. 创建文件结构
- 使用数字前缀命名文件（01、02、03...）
- 文件名清晰反映功能内容
- 保留间隔便于插入新功能

### 5. 编写README.md索引
- 提供系统概述
- 列出所有功能模块及对应文件
- 说明开发顺序和依赖关系
- 包含非核心功能模块引用

### 6. 创建各功能文档
- 为每个功能创建独立文档
- 包含功能描述、技术要点、交互设计
- 保持文档结构和格式统一

### 7. 验证一致性
- 确保文件名与README.md引用一致
- 检查所有引用文件都已创建
- 验证内容与文件名描述相符

## 示例模板

```
# [系统名称] 功能文档

## 系统概述
[简要描述系统核心功能和架构]

## 功能模块（按开发顺序）

1. [00_系统总览.md](00_系统总览.md) - 系统整体概述
2. [01_基础框架.md](01_基础框架.md) - 基础架构与核心组件
3. [02_核心功能A.md](02_核心功能A.md) - [描述]
4. [03_核心功能B.md](03_核心功能B.md) - [描述]
...

## 其他功能模块
- [功能X.md](功能X.md) - [描述]
- [功能Y.md](功能Y.md) - [描述]
```

## 最佳实践

- **模块化思维**：将复杂系统分解为独立但关联的模块
- **依赖关系清晰**：明确各模块间依赖，指导开发顺序
- **命名规范**：使用一致的命名规范，便于理解和维护
- **文档先行**：先创建文档结构，再填充具体内容
- **持续更新**：随需求变化及时更新文档结构

使用此技能时，请提供需求文档或描述需要分解的系统/产品，然后按照上述步骤执行。无需任何具体的技术实现或代码。
