# 三国志策略游戏需求文档

## 1. 游戏概述

### 1.1 游戏类型
- 单机桌面策略游戏
- 实时策略玩法
- 基于三国历史背景

### 1.2 游戏目标
- 玩家扮演三国时期的一位君主
- 通过军事、外交、经济等手段统一三国

### 1.3 目标用户
- 喜欢策略游戏的玩家
- 对三国历史感兴趣的玩家

### 1.4 游戏玩法
- 玩家开局选择扮演的势力君主
- 玩家可控制游戏时间，暂停或加速
- 每个势力会控制至少一座城池，且每个城池只能被一个势力控制
- 玩家以东汉未央宫全景地图为游戏的主界面
- 依据东汉的史实，未央宫内各处建筑，处理不同类型的事件。
- 玩家会遇到各类随机事件，如天灾、内政事件
- 玩家只能通过朝会决策控制，发出指令，最终决定游戏走向
- **每月初一的大朝会**：参加的官员提出各种提案，玩家作为君主进行选择和决策，影响本势力的数据（如军事、农业、科技发展等）
- **紧急朝会**：应对突发事件，需要玩家快速决策
- 玩家不能直接指挥军事战斗，只能通过战报接受信息，通过朝会决策
- 玩家可通过地图查看自家势力的各个城市的详细信息，包括城市名称、当前人口、资源分布等
- 地方势力的城市、道路等信息无法在地图上查看，有迷雾，只能通过情报获取

## 2. 核心功能需求
### 2.1 UI系统
- 以东汉未央宫全景地图为核心，作为整个游戏的主界面。玩家通过点击不同宫殿处理各类政务，体现前朝后宫严格分离的历史真实机制。
- 点击进入不同的宫殿，以宫殿内部的详细界面展示该宫殿的功能、人员、状态等信息，并可点击人员提供事件、对话等功能，以此操作。

**前朝区域**：开朝会，处理内政、外交、军事等政务
- 宣室殿：处理紧急朝会，应对突发事件
- 承明殿：处理每月初一的大朝会

**后宫区域**：处理后宫事务
- 椒房殿：后宫管理
- 长乐宫：皇室事务

### 2.2 地图系统
- **功能描述**：显示三国时期的中国地图，采用2D平面视角
- **具体要求**：
  - 2D平面地图，俯视视角
  - 包含著名城池、关隘和地形
  - 不同颜色表示不同势力控制区域
  - 点击城池/关隘可查看详细信息
  - 地图支持缩放和拖动
  - 显示连接各地点的道路系统

- **2D地图特性**：
  - 地形标识：使用不同颜色和图案标识山脉、丘陵、平原、河流等地形
  - 城池图标：使用简洁的图标表示不同等级的城池
  - 道路显示：清晰显示连接各地点的道路系统
  - 势力区域：使用不同颜色区分各势力控制区域
  - 信息展示：地图上直接显示关键信息，如城池名称、军队数量等
  - 简洁明了：注重信息展示的清晰度，而非视觉效果

- **地图交互功能**：
  - 缩放功能：鼠标滚轮或界面按钮控制地图缩放
  - 拖动浏览：支持鼠标拖动查看不同区域
  - 信息提示：鼠标悬停显示地点详细信息
  - 选中效果：选中的城池/单位有高亮效果
  - 路径预览：军队移动前显示路径预览

- **著名城池**：
  - 北方：洛阳、长安、许昌、邺城、襄平
  - 中原：徐州、下邳、小沛、陈留、汝南
  - 西南：成都、汉中、永安、江州、梓潼
  - 东南：建业、吴郡、会稽、柴桑、江夏
  - 荆州：襄阳、江陵、长沙、武陵、零陵、桂阳
  - 西北：天水、安定、南安、武都、西凉

- **重要关隘**：
  - 北方：雁门关、居庸关、山海关
  - 中原：虎牢关、潼关、函谷关
  - 西南：剑阁、阳平关、米仓关
  - 东南：濡须口、合肥、荆州关
  - 西北：街亭、祁山、陈仓

- **道路系统**：
  - 主要道路：连接各大城池的官道
  - 次要道路：连接小城池和关隘的支路
  - 特殊地形：山地、河流、森林对移动速度的影响
  - 道路等级：不同等级道路影响军队移动速度
  - 河流补给：沿河流行军的军队可获得补给加成，减少军粮消耗


### 2.6 战斗系统
- **功能描述**：采用宏观战略指挥模式
- **具体要求**：
  - 朝会决策：军事行动通过朝会系统决策，包含将领人选、进军路线、作战策略等
  - 自动执行：君主决策后，军队自动出征，玩家不进行实时指挥
  - 战报系统：军队出征后，通过延时战报回传战斗情况和结果
  - 军队状态：军队具有移动速度、军粮消耗、士气等多种状态
  - 道路移动：军队沿道路移动，受地形和道路等级影响
  - 自动战斗：具体战斗由部队根据将领能力和兵力自动进行

- **军事决策内容**：
  - 将领选择：根据武将能力选择合适的统帅
  - 进军路线：规划军队的行进路线，考虑地形、敌情和补给
  - 作战策略：选择进攻、防守、游击等不同作战策略
  - 兵力配置：决定出征的军队规模和兵种构成
  - 后勤保障：安排军粮补给和后勤支持

- **军队状态系统**：
  - 移动状态：当前位置、目标位置、移动速度
  - 补给状态：军粮数量、消耗速度、补给线状态
  - 士气状态：当前士气值、影响因素（胜负、补给、将领魅力等）
  - 疲劳状态：行军疲劳度、休息恢复
  - 伤兵状态：伤兵数量、治疗效果
  - 训练状态：训练度、影响战斗力
  - 装备状态：装备质量、影响攻防能力

- **军队训练系统**：
  - 训练设施：兵营、训练场等设施提升训练效率
  - 训练效果：提升军队士气、训练度、战斗力
  - 训练消耗：消耗金钱、时间和资源
  - 训练效果衰减：长期不训练会导致训练度下降

- **装备系统**：
  - 装备类型：布铠、皮铠、铁铠等不同材质的装备
  - 装备制造：城池工坊可制造不同类型装备
  - 装备效果：不同材质装备提供不同防御力
  - 装备维护：装备需要维护，否则效果下降
  - 装备损耗：战斗会导致装备损耗，需要修复或更换

- **战报系统**：
  - 行军报告：军队移动情况、遭遇事件
  - 战斗报告：战斗过程、伤亡情况、胜负结果、装备损耗
  - 特殊事件：遭遇自然灾害、民众反应、意外发现
  - 战后总结：战斗评价、经验收获、战利品

- **自动战斗机制**：
  - 战力计算：根据兵力、将领能力、装备、训练度等因素计算战斗力
  - 战斗模拟：基于双方战力和策略进行战斗模拟
  - 战斗过程：简化为几个关键阶段（接触、交锋、决胜、收尾）
  - 结果生成：根据战力差和随机因素生成战斗结果

### 2.10 朝会系统
- **功能描述**：模拟古代朝廷议事过程，让朝臣提出政见和方案
- **具体要求**：
  - 定期朝会：每月初一自动触发朝会
  - 朝臣参与：玩家手下的武将可作为朝臣参与议事
  - 议题生成：根据当前局势自动生成朝会议题
  - 意见提出：朝臣根据自己的属性和立场提出不同意见
  - 方案选择：君主（玩家）从多个方案中选择执行
  - 结果影响：不同选择会对国家产生不同影响

- **朝会议题类型**：
  - 军事议题：出征、防御、军备建设等
  - 经济议题：税收、贸易、基础设施建设等
  - 外交议题：结盟、宣战、通商、联姻等
  - 内政议题：法律、官员任命、民生问题等
  - 特殊事件：自然灾害、民众起义、边境冲突等

- **朝臣意见系统**：
  - 意见多样性：不同性格和能力的朝臣有不同观点
  - 立场影响：文臣偏重内政，武将偏重军事
  - 忠诚度影响：忠诚度低的朝臣可能提出自私的建议
  - 智力影响：智力高的朝臣提出更优方案
  - 关系影响：朝臣间关系好坏影响他们是否支持对方提议

- **决策后果系统**：
  - 短期效果：立即产生的资源变化、民心变化等
  - 长期影响：对国家发展方向和实力的影响
  - 朝臣反应：决策会影响朝臣对君主的忠诚度和关系
  - 历史记录：重要决策会被记录，影响历史评价
  - 数值影响：决策后果会直接作用到本势力的各项数值上，包括：
    - 军事力量：军队数量、训练水平、装备质量
    - 经济发展：农业产量、商业收入、资源储备
    - 科技水平：研究进度、技术应用、创新能力
    - 民心稳定：民众满意度、治安水平、文化认同
    - 外交关系：与其他势力的友好度、联盟状态、贸易往来

### 2.10.1 游戏进度机制
- **事件驱动系统**：游戏进度主要依靠事件系统推动，包括：
  - 定期事件：每月初一的大朝会
  - 随机事件：自然灾害、民众起义、边境冲突等
  - 历史事件：在特定时间点触发的重大历史事件
- **历史事件系统**：
  - 时间触发：根据三国历史时间线，在特定年份触发历史事件
  - 条件触发：当玩家势力达到特定条件时触发相关历史事件
  - 事件影响：历史事件会对游戏局势产生重大影响，推动游戏进程
  - 历史还原：重要历史事件如黄巾起义、董卓之乱、官渡之战等会按历史时间线发生

### 2.11 官职爵位系统
- **功能描述**：管理武将的官职、勋号和爵位，符合东汉史实
- **具体要求**：
  - 官职体系：采用东汉时期的官职体系，包括中央和地方官职
  - 爵位系统：按照东汉爵位制度，设置不同等级的爵位
  - 勋号授予：根据功绩授予相应的勋号和荣誉
  - 任命机制：君主可以任命武将担任不同官职
  - 权限影响：不同官职有不同的权限和影响力
  - 俸禄系统：官职和爵位决定武将的俸禄

- **东汉官职体系**：
  - 三公：太尉、司徒、司空（最高官职）
  - 九卿：太常、光禄勋、卫尉、太仆、廷尉、大鸿胪、宗正、大司农、少府
  - 将军：大将军、骠骑将军、车骑将军、卫将军、前后左右将军
  - 地方官职：州牧、太守、都尉、县令、县长
  - 军职：中郎将、校尉、都尉、司马、军侯

- **东汉爵位系统**：
  - 王爵：亲王、郡王（皇室成员）
  - 侯爵：县侯、乡侯、亭侯（功臣封赏）
  - 伯爵：县伯（高级官员）
  - 子爵：县子（中级官员）
  - 男爵：县男（低级官员）

- **勋号系统**：
  - 军功勋号：破虏将军、讨逆将军、平西将军等
  - 文治勋号：辅国将军、安国将军等
  - 特殊勋号：忠勇、智勇、仁勇等个人品质称号

- **官职功能**：
  - 朝会发言权：高级官职在朝会中有更大影响力
  - 军队指挥权：将军官职可以统帅军队
  - 行政管理权：地方官职可以管理城池
  - 资源获取：高官职可以获得更多俸禄和资源

- **晋升机制**：
  - 功绩晋升：根据战功和政绩提升官职爵位
  - 君主任命：由君主直接任命和罢免
  - 朝议推举：高级官职可通过朝议推举产生
  - 世袭制度：部分爵位可以世袭

### 2.12 事件库系统
- **功能描述**：管理游戏中的随机事件和历史事件，增加游戏变化性和历史真实感
- **具体要求**：
  - 事件分类：随机事件、历史事件、季节事件、特殊事件
  - 事件触发：根据时间、地点、条件触发相应事件
  - 事件处理：提供多个选项供玩家选择，不同选择产生不同结果
  - 事件影响：事件对游戏世界、资源、人物关系等产生影响
  - 事件记录：重要事件会被记录，影响历史评价

- **随机事件系统**：
  - 自然灾害：洪水、干旱、地震、蝗灾等
  - 社会事件：民众起义、盗匪横行、瘟疫爆发等
  - 经济事件：商业繁荣、经济危机、资源发现等
  - 人物事件：武将生病、武将叛变、人才来访等
  - 军事事件：军队哗变、边境冲突、敌军偷袭等

- **历史事件系统**：
  - 重大历史事件：黄巾起义、董卓之乱、官渡之战、赤壁之战等
  - 人物历史事件：三顾茅庐、草船借箭、空城计等
  - 地方历史事件：各地发生的历史小事件
  - 文化历史事件：节日庆典、风俗活动等
  - 科技历史事件：重要发明、技术进步等

- **事件触发机制**：
  - 时间触发：特定年份、季节、月份触发
  - 地点触发：特定城池、地区触发
  - 条件触发：满足特定资源、人物、关系条件触发
  - 概率触发：根据概率随机触发
  - 连锁触发：一个事件可能引发其他事件

- **事件处理系统**：
  - 选项设计：每个事件提供2-4个选项
  - 选项效果：不同选项产生不同效果
  - 选项限制：某些选项需要特定条件才能选择
  - 选项后果：选择会影响后续事件和游戏走向
  - 选项反馈：选择后立即显示直接效果

- **事件影响系统**：
  - 资源影响：增加或减少金钱、粮食等资源
  - 人物影响：改变武将属性、关系、忠诚度
  - 城池影响：改变城池人口、民心、发展度
  - 军事影响：影响军队士气、训练度、装备
  - 外交影响：改变与其他势力的关系
  - 历史影响：影响历史评价和结局

### 2.13 电脑AI系统
- **功能描述**：控制非玩家势力的行为，提供具有挑战性的游戏对手
- **具体要求**：
  - AI势力：控制魏、蜀、吴等非玩家势力
  - AI决策：基于多种因素进行决策，包括资源、军事、外交等
  - AI难度：提供不同难度级别的AI，适应不同水平玩家
  - AI个性：不同势力有不同的AI个性，符合历史人物特点
  - AI学习：AI能够根据玩家行为调整策略

- **AI个性系统**：
  - 激进型：偏好军事扩张，主动进攻
  - 保守型：注重防御和发展，谨慎行动
  - 平衡型：兼顾军事和内政，稳健发展
  - 外交型：重视外交关系，擅长合纵连横
  - 经济型：专注经济发展，积累资源

- **AI难度等级**：
  - 简单：资源加成，决策失误较多，反应较慢
  - 普通：标准资源，决策合理，反应正常
  - 困难：资源减少，决策精准，反应迅速
  - 专家：资源大幅减少，决策优秀，预判玩家行为

### 2.14 实时游戏系统
- **功能描述**：控制游戏进程和时间流逝
- **具体要求**：
  - 实时流逝的游戏时间（可暂停、加速）
  - 时间速度控制：正常、2倍速、4倍速、暂停
  - 实时显示当前日期和时间
  - 季节变化对游戏的影响
  - 军队实时移动和战斗
  - AI势力实时决策和行动

- **时间系统**：
  - 游戏时间流速：1秒现实时间 = 1天游戏时间（正常速度）
  - 季节系统：春、夏、秋、冬四季循环
  - 年份显示：从公元189年开始
  - 特殊日期：历史事件触发日期

- **实时军事行动**：
  - 军队在地图上沿道路自动移动
  - 移动速度受道路等级、地形和军队状态影响
  - 军粮消耗根据军队规模和移动距离计算
  - 到达目的地或遭遇敌军时自动触发事件
  - 战斗在军队相遇时自动进行，通过战报告知结果


## 4. 游戏流程设计

### 4.1 游戏启动流程
1. 游戏初始化：加载资源、初始化数据
2. 主菜单显示：新游戏、继续游戏、设置、退出
3. 势力选择：玩家选择扮演的势力
4. 游戏开始：进入游戏主界面

### 4.2 游戏循环流程
1. 时间推进：更新游戏状态
2. 事件触发：检查并触发随机事件
3. 朝会决策：处理朝会议题
4. 军事行动：执行军事决策
5. 内政管理：处理城池发展
6. 外交活动：处理外交关系


### 4.3 朝会流程
1. 朝会准备：确定参与朝会的朝臣
2. 议题生成：根据当前局势生成议题
3. 意见提出：朝臣根据属性提出意见
4. 方案选择：玩家选择执行方案
5. 决策执行：执行玩家选择的方案
6. 结果反馈：显示决策结果和影响

### 4.4 军事行动流程
1. 朝会决策阶段：
   - 朝臣提出军事行动建议（将领、路线、策略等）
   - 君主选择军事方案
   - 确定军队编制和后勤保障

2. 军队出征阶段：
   - 根据决策组建军队
   - 军队从出发城池开始沿道路移动
   - 系统计算移动速度和军粮消耗

3. 行军过程阶段：
   - 军队按计划路线自动移动
   - 定期生成行军报告（位置、状态、遭遇事件）
   - 更新军队状态（士气、疲劳、补给等）

4. 战斗触发阶段：
   - 军队遭遇敌军时自动触发战斗
   - 根据双方战力和将领能力进行战斗模拟
   - 生成战斗报告和结果

5. 战后处理阶段：
   - 更新军队状态和位置
   - 处理伤兵和战利品
   - 根据结果调整后续行动

### 4.5 战斗流程
1. 战斗准备：
   - 系统检测双方军队遭遇
   - 分析地形、天气等环境因素
   - 计算双方初始战力

2. 战斗模拟：
   - 根据将领能力和军队属性计算战斗力
   - 考虑地形、士气、疲劳等因素影响
   - 模拟战斗过程，计算伤亡

3. 战斗结果：
   - 确定胜负结果
   - 计算双方伤亡和损失
   - 生成战斗报告

4. 战后处理：
   - 更新军队状态和位置
   - 处理伤兵和战利品
   - 更新将领经验和声望

### 4.6 事件处理流程
1. 事件检测：系统检查事件触发条件
2. 事件生成：根据条件生成相应事件
3. 事件展示：向玩家展示事件描述和背景
4. 选项选择：玩家选择处理事件的方案
5. 结果执行：执行选择的结果
6. 影响更新：更新游戏世界状态

### 4.7 官职爵位管理流程
1. 任命流程：
   - 君主选择武将和空缺官职
   - 系统检查武将是否符合任职条件
   - 朝会讨论（高级官职需要）
   - 正式任命并记录

2. 晋升流程：
   - 系统根据功绩自动推荐可晋升武将
   - 君主审查推荐名单
   - 朝会讨论（高级爵位需要）
   - 正式晋升并更新待遇

3. 罢免流程：
   - 君主选择要罢免的武将
   - 系统评估罢免影响
   - 执行罢免并调整关系

4. 世袭流程：
   - 检查可世袭爵位
   - 确定继承人
   - 办理继承手续

### 4.8 历史事件触发流程
1. 事件准备阶段：
   - 系统根据历史时间线准备即将发生的历史事件
   - 检查玩家当前状态和位置
   - 确定玩家是否可以参与该事件

2. 事件预告阶段：
   - 提前向玩家预告即将发生的历史事件
   - 提供历史背景和可能的影响
   - 给玩家准备时间

3. 事件触发阶段：
   - 在历史时间点触发事件
   - 根据玩家位置和状态决定参与方式
   - 生成与事件相关的朝会议题

4. 玩家参与阶段：
   - 玩家通过朝会决策参与历史事件
   - 玩家的决策可能影响事件的细节
   - 记录玩家的选择和影响

5. 事件结果阶段：
   - 根据历史事实和玩家选择生成事件结果
   - 更新游戏世界状态
   - 记录事件对后续发展的影响

## 5. 视觉设计规范

### 5.1 设计理念与原则
整体采用中国传统水墨山水画的艺术风格，以"墨分五色"（焦、浓、重、淡、清）的表现手法，结合留白艺术，营造出古朴典雅、意境深远的三国战场氛围。通过简约而不简单的视觉表现，展现中国传统文化之美，与三国历史背景完美契合。


### 5.6 用户交互设计
- **缩放操作**：鼠标滚轮缩放，或使用界面按钮
- **拖动操作**：鼠标左键拖拽平移地图
- **选择操作**：点击选择城池或单位
- **信息查看**：悬停显示详细信息

### 5.7 历史地理真实性
- **地理依据**：地图基于东汉末年的历史地理资料，包括《汉书·地理志》、《后汉书·郡国志》等
- **城池位置**：所有城池按照历史地理位置精确放置，考虑当时的行政区划
- **地形表现**：山脉、河流、平原等地形符合历史地理状况，采用墨色山水风格表现
- **交通路线**：主要道路、关隘、渡口等符合历史交通状况，考虑当时的交通技术
- **行政区划**：州、郡、县等行政区划符合东汉末年的行政制度
- **历史变迁**：考虑东汉末年的地理变迁，如黄河改道、城市兴衰等

## 6. MVP（最小可行产品）定义

### 6.1 核心功能
- **基础UI系统**：未央宫全景地图，前朝后宫分区
- **朝会系统**：每月初一的大朝会和紧急朝会
- **决策系统**：
  - 提案展示：官员提案的界面展示和内容呈现
  - 选择机制：玩家选择不同提案的交互方式
  - 决策确认：玩家确认决策的流程和反馈
  - 结果反馈：决策后立即显示数值变化的反馈机制
- **数值系统**：军事、经济、科技、民心、外交五项基础数值
- **基础地图系统**：2D平面地图，显示城池和势力控制区域

### 6.2 最小内容
- **基础官员系统**：10-15名基础官员，不同属性和立场
- **基础提案库**：30-50个基础提案，涵盖军事、经济、外交、内政
- **基础事件系统**：10-15个随机事件和5-10个关键历史事件
- **基础势力系统**：玩家控制一个势力，2-3个AI控制的敌对势力

### 6.3 开发优先级
1. **第一优先级**：UI系统、朝会系统、决策系统
2. **第二优先级**：数值系统、基础官员系统、基础提案库
3. **第三优先级**：地图系统、基础事件系统、基础势力系统

### 6.4 成功标准
- 玩家能够完整体验一次"每月朝会-决策-数值变化"的完整流程
- 游戏能够运行至少12个游戏月份（一年）
- 基础数值系统能正确反映玩家决策的影响
- UI界面操作流畅，无明显bug
