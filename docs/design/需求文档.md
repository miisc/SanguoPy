# 三国志策略游戏需求文档

## 1. 游戏概述

### 1.1 游戏类型
- 单机桌面策略游戏
- 实时策略玩法
- 基于三国历史背景

### 1.2 游戏目标
- 玩家扮演三国时期的一位君主
- 通过军事、外交、经济等手段统一三国

### 1.3 目标用户
- 喜欢策略游戏的玩家
- 对三国历史感兴趣的玩家

### 1.4 游戏玩法
- 玩家开局选择扮演的势力君主
- 玩家可控制游戏时间，暂停或加速
- 每个势力会控制至少一座城池，且每个城池只能被一个势力控制
- 玩家以东汉未央宫全景地图为游戏的主界面
- 依据东汉的史实，未央宫内各处建筑，处理不同类型的事件。
- 玩家会遇到各类随机事件，如天灾、内政事件
- 玩家只能通过朝会决策控制，发出指令，最终决定游戏走向
- **每月初一的大朝会**：参加的官员提出各种提案，玩家作为君主进行选择和决策，影响本势力的数据（如军事、农业、科技发展等）
- **紧急朝会**：应对突发事件，需要玩家快速决策
- 玩家不能直接指挥军事战斗，只能通过战报接受信息，通过朝会决策
- 玩家可通过地图查看自家势力的各个城市的详细信息，包括城市名称、当前人口、资源分布等
- 地方势力的城市、道路等信息无法在地图上查看，有迷雾，只能通过情报获取

## 2. 核心功能需求

### 2.1 AI系统架构

#### 2.1.1 总体架构
采用三层AI架构设计：
- **战术层（状态机）**：处理具体战斗和短期决策
- **战略层（行为树）**：制定中期发展规划和资源配置
- **政治层（LLM）**：处理复杂外交关系和长远国策

#### 2.1.2 战术层（状态机）
- **功能**：处理具体战斗场景和短期军事行动
- **状态节点**：
  - 待命状态：军队驻扎，等待指令
  - 行军状态：沿道路移动至目标位置
  - 侦查状态：探索未知区域，收集情报
  - 攻击状态：与敌军交战
  - 防御状态：固守城池或阵地
  - 撤退状态：有序撤退，保存实力
- **转换条件**：基于敌情、地形、补给等因素触发状态转换

#### 2.1.3 战略层（行为树）
- **功能**：制定中期发展战略和资源配置计划
- **核心行为**：
  - 资源评估：分析当前资源状况和需求
  - 发展规划：制定农业、商业、军事发展计划
  - 外交策略：处理与其他势力的关系
  - 军事部署：安排军队调动和防御布局
- **决策机制**：基于当前局势和长期目标进行综合评估

#### 2.1.4 政治层（LLM）
- **功能**：处理复杂的外交关系和长远国策制定
- **主要任务**：
  - 外交谈判：与其他势力进行结盟、通商等谈判
  - 政策制定：制定税收、法律等内政政策
  - 人才培养：选拔和任用官员、将领
  - 历史事件处理：应对重大历史事件和危机
- **优势**：能够处理模糊、复杂的决策场景，提供更具创造性的解决方案

#### 2.1.5 层间协作机制
- **信息传递**：下层向上层汇报状态，上层向下层下达指令
- **冲突解决**：当不同层级产生冲突时，采用协商机制解决
- **动态调整**：根据游戏进程和玩家行为，动态调整各层权重

### 2.2 UI系统
- 以东汉未央宫全景地图为核心，作为整个游戏的主界面。玩家通过点击不同宫殿处理各类政务，体现前朝后宫严格分离的历史真实机制。
- 点击进入不同的宫殿，以宫殿内部的详细界面展示该宫殿的功能、人员、状态等信息，并可点击人员提供事件、对话等功能，以此操作。

**前朝区域**：开朝会，处理内政、外交、军事等政务
- 宣室殿：处理紧急朝会，应对突发事件
- 承明殿：处理每月初一的大朝会

**后宫区域**：处理后宫事务
- 椒房殿：后宫管理
- 长乐宫：皇室事务

### 2.3 地图系统
- **功能描述**：显示三国时期的中国地图，作为朝会议案的核心决策参考
- **具体要求**：
  - 2D平面地图，俯视视角，采用中国传统水墨画风格
  - **嵌入式设计**：在朝会议案描述下方直接显示（非弹窗），宽度=描述区域100%，高度=描述区域1/3
  - **三方可见性规则**：
    * 我方控制区：城市和道路**永久清晰可见**
    * 敌方控制区：城市和道路**完全迷雾覆盖**（纯黑色）
    * 情报解锁区：仅显示**已解锁**的城市和道路
  - **道路可见性规则**：
    * 所有连接我方城市的道路**全程可见**（包括延伸至敌方区域的路段）
    * 敌方区域内道路**完全隐藏**，除非通过情报解锁
    * 情报解锁后，仅显示**已解锁道路**（非全区域解锁）
  - **道路类型与效果**：
    | 类型 | 行军速度系数 | 军粮消耗系数 | 可见性规则 |
    |------|------------|------------|-----------|
    | 官道 | 1.0 | 1.0 | 我方永久可见 |
    | 山间小径 | 0.6 | 1.2 | 需情报解锁 |
    | 水路 | 0.8 | **0.6** | 需情报解锁 |
  - **动态聚焦机制**：自动定位议案关联区域（如讨论"汉中防御"时地图中心定位汉中）
  - **行军约束**：
    * 军队**只能沿已知道路**移动
    * 行军至我方道路末端（边界点）时**自动暂停**
    * 未解锁区域**无法规划行军路线**
  - **情报交互**：
    * 点击迷雾区域显示："需消耗X情报点解锁"
    * 解锁成功后地图**实时刷新**可见区域
    * 情报时效性：临时性情报(1-3个月) vs 持久性情报

### 2.4 战斗系统
- **功能描述**：采用宏观战略指挥模式
- **具体要求**：
  - 朝会决策：军事行动通过朝会系统决策，包含将领人选、进军路线、作战策略等
  - 自动执行：君主决策后，军队自动出征，玩家不进行实时指挥
  - 战报系统：军队出征后，通过延时战报回传战斗情况和结果
  - 军队状态：军队具有移动速度、军粮消耗、士气等多种状态
  - 道路移动：军队沿道路移动，受地形和道路等级影响
  - **道路行军规则**：
    * 军队**必须沿道路移动**，受道路类型影响
    * 水路**无需水军科技**，仅**降低40%军粮消耗**
    * 军粮消耗计算：基础消耗 = 军队规模 × 行军天数 × 道路军粮系数
    * **行军终止机制**：抵达迷雾区域边界时自动暂停，需情报解锁才能继续
  - **自动战斗**：具体战斗由部队根据将领能力和兵力自动进行，但**行军路线必须由玩家通过朝会决策确定**

### 2.5 朝会系统
- **功能描述**：模拟古代朝廷议事过程，让朝臣提出政见和方案
- **具体要求**：
  - 定期朝会：每月初一自动触发朝会
  - 朝臣参与：玩家手下的武将可作为朝臣参与议事
  - 议题生成：根据当前局势自动生成朝会议题
  - 意见提出：朝臣根据自己的属性和立场提出不同意见
  - 方案选择：君主（玩家）从多个方案中选择执行
  - 结果影响：不同选择会对国家产生不同影响
  - **地图集成**：
    * 每个军事/内政议案**下方嵌入地图控件**
    * 地图自动显示议案关联区域和**可行行军路线**
    * **军粮消耗对比**：在地图旁显示不同路线的军粮消耗对比
    * **情报提示**：迷雾区域显示解锁所需情报成本
  - **决策支持**：
    * 系统自动计算**最短可行路线**（基于已知道路）
    * 军事提案必须包含**行军路线可行性分析**

### 2.6 官职爵位系统
- **功能描述**：管理武将的官职、勋号和爵位，符合东汉史实
- **具体要求**：
  - 官职体系：采用东汉时期的官职体系，包括中央和地方官职
  - 爵位系统：按照东汉爵位制度，设置不同等级的爵位
  - 勋号授予：根据功绩授予相应的勋号和荣誉
  - 任命机制：君主可以任命武将担任不同官职
  - 权限影响：不同官职有不同的权限和影响力
  - 俸禄系统：官职和爵位决定武将的俸禄

### 2.7 事件库系统
- **功能描述**：管理游戏中的随机事件和历史事件，增加游戏变化性和历史真实感
- **具体要求**：
  - 事件分类：随机事件、历史事件、季节事件、特殊事件
  - 事件触发：根据时间、地点、条件触发相应事件
  - 事件处理：提供多个选项供玩家选择，不同选择产生不同结果
  - 事件影响：事件对游戏世界、资源、人物关系等产生影响
  - 事件记录：重要事件会被记录，影响历史评价
  - **情报事件扩展**：
    * **城市级解锁**：消耗情报点解锁单个城市
    * **道路级解锁**：消耗情报点解锁特定道路
    * **区域级解锁**：消耗大量情报点解锁3x3网格区域
    * **情报时效**：临时情报(1-3个月)需定期维护，持久情报需持续投入
  - **事件效果**：
    * 成功解锁后**实时更新地图可见性**
    * 解锁重要道路触发"战略通道开启"提示
    * 解锁敌方都城触发"重大情报突破"事件

### 2.8 电脑AI系统
- **功能描述**：控制非玩家势力的行为，提供具有挑战性的游戏对手
- **具体要求**：
  - AI势力：控制魏、蜀、吴等非玩家势力
  - AI决策：基于多种因素进行决策，包括资源、军事、外交等
  - AI难度：提供不同难度级别的AI，适应不同水平玩家
  - AI个性：不同势力有不同的AI个性，符合历史人物特点
  - AI学习：AI能够根据玩家行为调整策略

### 2.9 实时游戏系统
- **功能描述**：控制游戏进程和时间流逝
- **具体要求**：
  - 实时流逝的游戏时间（可暂停、加速）
  - 时间速度控制：正常、2倍速、4倍速、暂停
  - 实时显示当前日期和时间
  - 季节变化对游戏的影响
  - 军队实时移动和战斗
  - AI势力实时决策和行动

## 3. 技术实现要求

### 3.1 AI系统技术栈
- **状态机框架**：使用有限状态机（FSM）实现战术层
- **行为树引擎**：采用行为树（Behavior Tree）实现战略层
- **LLM集成**：集成大语言模型API实现政治层决策
- **协调机制**：开发层间通信和冲突解决模块

### 3.2 性能优化
- **计算资源分配**：根据不同层级的重要性和复杂度分配计算资源
- **缓存机制**：对频繁计算的结果进行缓存，提高响应速度
- **并行处理**：利用多线程技术并行处理不同层级的AI计算

### 3.3 数据管理
- 使用JSON格式存储游戏数据
- 实现数据持久化和加载机制
- 支持游戏存档和读档功能

### 3.4 网络通信
- 为未来多人游戏功能预留网络通信接口
- 实现基本的客户端-服务器通信框架

## 4. 游戏流程设计

### 4.1 游戏启动流程
1. 游戏初始化：加载资源、初始化数据
2. 主菜单显示：新游戏、继续游戏、设置、退出
3. 势力选择：玩家选择扮演的势力
4. 游戏开始：进入游戏主界面

### 4.2 游戏循环流程
1. 时间推进：更新游戏状态
2. 事件触发：检查并触发随机事件
3. 朝会决策：处理朝会议题
4. 军事行动：执行军事决策
5. 内政管理：处理城池发展
6. 外交活动：处理外交关系

### 4.3 AI决策流程
1. 状态评估：AI分析当前游戏状态
2. 目标设定：根据状态设定短期和长期目标
3. 行动规划：制定实现目标的具体行动计划
4. 决策执行：执行选定的行动方案
5. 结果评估：评估行动效果并调整策略

## 5. 视觉设计规范

### 5.1 设计理念与原则
整体采用中国传统水墨山水画的艺术风格，以"墨分五色"（焦、浓、重、淡、清）的表现手法，结合留白艺术，营造出古朴典雅、意境深远的三国战场氛围。通过简约而不简单的视觉表现，展现中国传统文化之美，与三国历史背景完美契合。

### 5.2 用户交互设计
- **缩放操作**：鼠标滚轮缩放，或使用界面按钮
- **拖动操作**：鼠标左键拖拽平移地图
- **选择操作**：点击选择城池或单位
- **信息查看**：悬停显示详细信息

## 6. MVP（最小可行产品）定义

### 6.1 核心功能
- **基础UI系统**：未央宫全景地图，前朝后宫分区
- **朝会系统**：每月初一的大朝会和紧急朝会
- **决策系统**：
  - 提案展示：官员提案的界面展示和内容呈现
  - 选择机制：玩家选择不同提案的交互方式
  - 决策确认：玩家确认决策的流程和反馈
  - 结果反馈：决策后立即显示数值变化的反馈机制
  - **地图集成**：议案描述下方嵌入式地图控件，显示：
    * 议案关联区域自动聚焦
    * 三方可见性（我方/敌方/解锁区）
    * 可行行军路线及军粮消耗
    * 情报解锁提示
- **数值系统**：军事、经济、科技、民心、外交五项基础数值
- **基础地图系统**：2D平面地图，显示城池和势力控制区域，**实施三方可见性规则**

### 6.2 最小内容
- **基础官员系统**：10-15名基础官员，不同属性和立场
- **基础提案库**：30-50个基础提案，涵盖军事、经济、外交、内政
- **基础事件系统**：10-15个随机事件和5-10个关键历史事件
- **基础情报系统**：
  * 3种情报解锁类型（城市/道路/区域）
  * 情报成本模型（金币+情报点）
  * 情报时效机制（临时/持久）
- **基础势力系统**：玩家控制一个势力，2-3个AI控制的敌对势力

### 6.3 开发优先级
1. **第一优先级**：UI系统、朝会系统、决策系统
2. **第二优先级**：数值系统、基础官员系统、基础提案库
3. **第三优先级**：地图系统（**含三方可见性规则**）、基础情报系统、基础势力系统

### 6.4 成功标准
- 玩家能够完整体验一次"每月朝会-决策-数值变化"的完整流程
- 游戏能够运行至少12个游戏月份（一年）
- 基础数值系统能正确反映玩家决策的影响
- **地图系统能准确实现三方可见性规则**
- **军事决策能正确计算不同路线的军粮消耗**
- UI界面操作流畅，无明显bug
