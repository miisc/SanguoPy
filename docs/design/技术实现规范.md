# 三国志策略游戏技术实现规范

## 1. 开发框架

### 1.1 主要框架
- **GUI框架**: PyQt5/PyQt6
- **编程语言**: Python 3.8+
- **架构模式**: MVC (Model-View-Controller)
- **数据存储**: JSON文件 + SQLite数据库（可选）

### 1.2 项目结构
```
SanGuoHtmlDemo/
├── main.py                 # 主入口文件
├── game/                   # 游戏核心模块
│   ├── __init__.py

│   ├── game_model.py       # 游戏数据模型 (Model)
│   └── game_view.py        # 游戏视图界面 (View)

│   ├── __init__.py

│   ├── court_dialog.py     # 朝会对话框
```

## 2. 技术架构

### 2.1 MVC架构设计

#### Model层 (游戏数据模型)
- **GameModel**: 游戏状态管理器
  - 管理游戏时间、资源、势力关系
  - 处理城池、武将、军队等核心数据
  - 实现游戏规则和逻辑计算
  - 提供数据持久化接口

- **数据类**:
  - `City`: 城池数据模型
  - `General`: 武将数据模型  
  - `Army`: 军队数据模型
  - `CourtSession`: 朝会数据模型
  - `Technology`: 科技数据模型

#### View层 (用户界面)
- **MainWindow**: 主窗口
  - 顶部信息栏：显示年份、季节、资源
  - 中央地图区域：QGraphicsView实现
  - 底部控制栏：朝会、军事、内政等按钮

- **MapView**: 地图视图
  - 使用QGraphicsScene/QGraphicsView实现
  - 支持缩放、拖动、点击交互
  - 分层渲染：地形层、建筑层、单位层、UI层

- **Dialog组件**:
  - `CourtMeetingDialog`: 朝会对话框
  - `CityInfoDialog`: 城池信息对话框
  - `GeneralInfoDialog`: 武将信息对话框
  - `ArmyMovementDialog`: 军队移动对话框

#### Controller层 (游戏控制)
- **GameController**: 游戏控制器
  - 处理用户输入事件
  - 协调Model和View的交互
  - 管理游戏流程和状态转换
  - 调用AI决策系统

### 2.2 核心技术组件

#### 地图渲染系统
- **QGraphicsScene**: 作为地图容器
- **自定义QGraphicsItem**: 
  - `TerrainItem`: 地形块
  - `CityItem`: 城池建筑
  - `ArmyItem`: 军队单位
  - `RoadItem`: 道路连接

- **渲染优化**:
  - 视口裁剪：只渲染可见区域
  - LOD系统：根据缩放级别调整细节
  - 缓存机制：缓存常用图形资源

#### 事件处理系统
- **信号槽机制**: PyQt原生事件处理
- **自定义事件**: 游戏特定事件
- **定时器**: 游戏时间流逝控制

#### 数据持久化
- **JSON序列化**: 游戏数据保存/加载
- **自动存档**: 每回合结束时自动保存
- **手动存档**: 玩家主动保存游戏
- **多存档槽**: 支持多个存档文件

## 3. 核心功能实现

### 3.1 地图系统实现
- **伪3D效果**: 通过2D坐标计算实现等距投影
- **坐标转换**: 游戏坐标 ↔ 屏幕坐标
- **交互处理**: 鼠标点击、拖动、滚轮缩放
- **路径预览**: BFS算法计算最短路径

### 3.2 朝会系统实现
- **事件生成器**: `CourtEventGenerator`
- **事件队列**: `CourtEventQueue`
- **决策处理器**: `CourtDecisionHandler`
- **UI绑定**: 与对话框组件集成

### 3.3 军事系统实现
- **路径查找**: BFS算法实现道路网络路径查找
- **军队移动**: 定时器控制军队沿路径移动
- **战斗模拟**: 基于属性的战斗力计算
- **战报生成**: 自动生成战斗结果报告

### 3.4 AI系统实现
- **AI决策引擎**: `AIDecisionEngine`
- **加权评分系统**: 多因素综合评估
- **状态机**: 不同游戏状态采用不同策略
- **难度调节**: 资源、决策质量、反应速度调整

## 4. 性能优化

### 4.1 渲染性能
- **批量绘制**: 减少绘制调用次数
- **脏矩形更新**: 只重绘变化区域
- **异步加载**: 大型资源异步加载

### 4.2 内存管理
- **对象池**: 重用游戏对象
- **垃圾回收**: 及时释放不用的资源
- **内存监控**: 监控内存使用情况

### 4.3 计算优化
- **缓存机制**: 缓存计算结果
- **增量更新**: 只计算变化部分
- **多线程**: 耗时操作放入后台线程
